# 问题排查

[返回 README](../README.md)

| 现象 | 先检查什么 |
|---|---|
| 看不到“模型提供商” | 是否是 Hub 2.31.2；是否首次打补丁后从托盘完整退出并重新打开 |
| 找不到 app.asar | 使用 `-AsarPath` 指定正确的 `resources\app.asar`；不要填写 exe 路径 |
| Node 下载失败 | 检查官方源网络、代理与磁盘空间；也可预先安装带 npm 的 Node.js 24.5+ |
| SHA-256 不一致 | 停止安装，删除不完整下载并核对 Release 与官方源；不要跳过校验 |
| 端口 18925 已占用 | 核实是自己的桥还是其他程序；安装器不会强制接管陌生进程 |
| 页面提示后台版本过旧 | 用对应安装目录的 `restart-bridge.cmd` 重启桥，再点重试 |
| Google 登录转圈 | 确认原应用可以正常登录、桥在线、Google 代理可用；第三方 Key 不能替代 Google 登录 |
| 列表能获取但没有容量信息 | 接口可能只返回 ID；“自动配置”还会查询详情，再按已知表补齐 |
| 自动配置仍显示未识别 | 未获得可靠字段，当前值保留；按提供商文档手动填写，不代表发现了真实容量 |
| 聊天菜单仍有旧项 | 看保存状态，点击“刷新模型列表”；应用升级后可能需要适配原生接口 |
| 某个思考档位报错 | 检查提供商实际支持，取消不支持的档位；菜单可配置不等于上游全支持 |
| 智能体立即终止，日志含 MaxTokenLimit | 最大输出必须小于上下文窗口；不能把整个窗口都分配给输出。保存后刷新模型列表再试 |
| 一直“工作中” | 先看是否在推进不同工具步骤；多轮任务会累加每次上游等待。v1.5.4 第三方 API 错误会结束当前执行并显示原生重试入口；不会再因隐藏 API 重试反复等待。Google 模型及输出截断后的原生续写策略不变 |
| 日志含 upstream first-byte timeout | 默认 180 秒仍未收到上游首响应；列表能获取不代表生成接口可用。核对提供商状态，再手动重试或选择另一个已配置的提供商，不要重复提交同一任务 |
| 第三方请求后弹“身份验证已过期” | v1.5.6 及以前可能把提供商 401/403 误判为 Google 会话过期。v1.5.7 已隔离此类错误；先核对错误中的端点与 Google 用户状态，不要反复重新登录。`All available accounts exhausted` 是提供商的返回文字，需要核对其分组/账户池，不能据此断言 Google 登录失效 |
| 输入区显示“等待上游响应” | 本轮请求尚未收到上游响应头；状态行不是模型生成内容。请向供应商核对同一请求的入口、上游首事件、客户端首字节和完成时间，避免将计费成功等同于已流式返回 |
| 输入区显示“正在接收工具参数” | 工具参数确实在增量到达；显示字符数，只在参数完整、合法且流正常结束后才交给原生执行器，避免执行被截断的文件或命令 |
| 日志含 upstream stream idle timeout | 上游流在空闲期限内没有新数据；核对端点状态、模型参数与网络，避免盲目重复重试 |
| 大约 20 秒就失败 | 确认运行的是新桥；生成等待与连接探测使用不同期限 |
| 应用升级后失效 | 更新可能覆盖 asar 或改变原生组件；核对版本再应用，避免恢复跨版本旧备份 |

## Google 代理

读取顺序：`AGY_BRIDGE_GOOGLE_PROXY` → HTTP(S)/ALL_PROXY 环境变量 → Windows 当前用户系统代理。可将专用变量设为 `direct` 强制 Google 直连。第三方请求不自动使用该 Google 专用代理。

## 本地诊断

健康检查：

```powershell
Invoke-RestMethod http://127.0.0.1:18925/api/health
```

日志默认位于 `%LOCALAPPDATA%\agy-bridge\bridge.log`。错误报告只保留版本、脱敏模型名、错误代码、复现步骤和必要参数。不要附带 config.json、Cookie、OAuth 文件、完整请求正文或账号截图。

v1.5.1 默认关闭请求抓取；需要排查时才显式启用，完成后关闭并清理。更多边界见 [SECURITY.md](../SECURITY.md)。

原生错误策略随应用补丁加载。常规安装升级后，从托盘完全退出并重新打开一次；仅重启本地桥不会替换已运行的页面代码。失败时应看到“智能体执行因错误而终止”和手动重试入口；详细上游原因可按同一 trace 查本地日志。不要把短回复成功当作长代码任务已经通过，验收应包含实际工具执行、文件落盘和最终回复。
