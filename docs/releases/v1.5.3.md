# v1.5.3 · 容量校验修复 / Capacity validation fix

修复把“最大输出”设置为整个上下文窗口时，原生智能体在发送推理请求前直接终止的问题。

- 原生设置页、诊断页面和保存 API 均要求最大输出严格小于上下文窗口。
- 无效保存会保留原有提供商名称、密钥、模型映射及配置文件。
- 自动配置遇到矛盾的端点容量时保留原始数据并提示核对，避免把输出静默设为整个窗口。
- 补充输出截断、长时间等待与上游流超时的排查说明。

本地验证：38 项单元 / HTTP 集成检查、156 项协议检查、39 项新配置回归通过；独立安装器的安装、升级、Unicode 路径和回滚测试通过。远程 CI 未启用。

升级请使用本 Release 的 Windows ZIP。更新后台后运行安装目录中的 `restart-bridge.cmd`；应用界面补丁在下次完整启动时加载。日常修改模型仍使用热刷新。

**范围说明：** 此版本修复本地容量配置校验，不承诺消除提供商的生成延迟或超时。输出达到上限时，原生应用可能发起自动续写；较高思考强度及多轮工具任务需要同时考虑响应时间和输出预算。

---

This release prevents a native planner startup failure caused by setting maximum output equal to the entire context window.

- Both settings interfaces and the save API require maximum output to be strictly smaller than context.
- Rejected saves preserve provider names, secrets, model mappings and the configuration file.
- Discovery preserves conflicting endpoint values with a warning instead of silently assigning the full context to output.
- Troubleshooting now covers output-limit continuations, long generation waits and upstream stream timeouts.

Local validation passed: 38 unit/HTTP checks, 156 protocol assertions and 39 fresh-configuration checks, plus the isolated Windows installer fixture. Remote CI remains disabled.

After upgrading backend files, run `restart-bridge.cmd` in the installed directory. Updated application UI patches load on the next full application launch; normal model changes still refresh live.

This fixes local capacity validation. It does not guarantee faster provider generation or resolve every upstream timeout. Native continuation retries after an output limit can extend a task's total time.
